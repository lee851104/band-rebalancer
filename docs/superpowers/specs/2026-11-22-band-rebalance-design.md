# 倉位區間再平衡管理器：設計文件

日期：2026-11-22
規模：小型專案（短版設計文件）

## 目的與動機

仿照影片中的「容忍區間再平衡」做法管理自己的倉位：每個板塊有目標權重和允許區間，
只有權重超出區間時才調整，在區間內就一股不賣。使用者要用**手動填寫**的方式輸入持倉，
**不接 MCP、不接券商 API**，並用影片那種區間圖一眼看出各板塊的位置。

## 目標

- 用表單填寫持倉：代號、板塊、股數、價格。
- 設定各板塊的目標權重、區間下限、區間上限。
- 自動計算各板塊的實際權重，畫出區間圖：區間（虛線框）、目標（直線）、上次快照（灰點）、目前（橘點），並標示「區間內 ✓」或「超出上限 / 低於下限」。
- 存快照（日期 + 各持倉市值 + 各板塊權重），可以選兩個日期比較。
- 超出區間時，算出「拉回區間邊緣」和「拉回目標」各需要買賣多少金額（純算術，不是建議）。
- 匯出 / 匯入 JSON 備份。
- 用 GitHub Actions 部署到 GitHub Pages，手機和電腦都能用同一個網址打開。

## 非目標

- 不自動抓股價（第一版手動填價格）。
- 不同步多台裝置的資料（靠匯出 / 匯入搬資料）。
- 不下單、不接任何券商。
- 不提供配置建議，目標和區間由使用者自己設定。

## 反目標（做了反而算失敗）

- 持倉數字出現在 repo、網頁原始碼或任何伺服器上。
- 需要安裝 Python / Node 才能使用。

## 限制

- GitHub Pages 的網址是公開的，所以 repo 和網頁只放程式，**所有資料只存在使用者的瀏覽器（localStorage）**。
- 瀏覽器資料可能被清除，介面要提醒定期匯出備份。

## 考慮過的做法

1. **程式放 GitHub Pages，資料存在各自瀏覽器**（已選）：持倉不會公開，不需要後端；缺點是各裝置資料不同步。
2. 資料存在 repo，Actions 每天自動抓價更新：最自動化，但持倉會公開，要避免就得加密或付費，複雜度高。
3. 本機 HTML 或 Python Streamlit：使用者希望部署到 GitHub、能在多台裝置打開，所以不採用。

## 已決定的做法

- 純靜態網頁：HTML + CSS + 原生 JavaScript，不用框架、不需要 build 步驟。圖表用 SVG 手繪。（我的決定：最簡單，Actions 只要上傳檔案就能部署。）
- 介面使用繁體中文，深色主題，參考影片的配色。（我的決定）
- 權重 = 板塊市值 ÷ 全部持倉總市值。現金可以當成一個板塊填寫。（我的決定）
- 預設比較「最近一次快照」和「目前填寫的數字」，也可以自選兩個快照。（我的決定）
- GitHub Actions workflow：push 到 main 時，用官方的 Pages actions 部署。
- 資料格式有版本號，方便之後擴充。
