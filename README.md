# 區間再平衡

用「容忍區間」管理倉位的單頁網頁工具：替每個板塊設定目標權重和允許區間，填入持股後，一眼看出哪個板塊超出區間、最少要買賣多少。**在區間內就一股不賣，只有超出區間才調整。**

- 一頁看完：配置圓環、一句話結論、每個板塊的區間圖、展開看持股。
- 直接在圖上拖曳設定區間與目標，不用填表。
- 美股代號模糊搜尋（打錯字也找得到），可選用 Finnhub 免費金鑰查最新價格。
- **持股數量只存在你這台裝置的瀏覽器**，網站上沒有任何人的持股。
- 預設深色，手機、電腦都能用。

> 試算金額只是算術（假設總市值不變、買賣的錢進出現金），不是投資建議。

## 網址

部署後的網址：`https://<你的 GitHub 帳號>.github.io/<repo 名稱>/`

## 怎麼用

1. 第一次打開時選「載入範例資料」先看看效果（數字都是虛構的），或選「從空白開始」。
2. **設定區間**：在每個板塊那一列
   - 拖曳藍框的左右兩端 → 設定下限、上限
   - 拖曳黑色目標線 → 設定目標（目標跑出區間時，區間會整段跟著移動）
   - 也可以用 Tab 選到把手，再用左右方向鍵微調（每次 0.5%，按住 Shift 每次 5%）
   - 右上方「區間 ±3 點 / ±5 點 / ±25%」可以一次套用到所有板塊
   - 目標加起來不是 100% 時，按「補成 100%」會依比例調整
3. **填持股**：點板塊名稱展開 → 「新增持股」→ 輸入代號或公司名搜尋 → 填股數。
   - 現金：代號填 `USD`，股數填金額，價格會自動設為 1。
4. **看結果**：
   - 上方大字直接告訴你幾個板塊超出區間，點按鈕會跳到那個板塊。
   - 綠色「區間內」不用動；紅色會寫出「賣出 / 買入 多少」才能回到區間。
   - 展開板塊可以看到回到目標要多少、以及每檔持股的佔比。

## 最新價格（選用）

1. 到 [finnhub.io](https://finnhub.io/register) 免費註冊，在 Dashboard 複製 API Key。
2. 在網頁右上角「⋯ → 報價設定」貼上，按「測試並儲存」。
3. 之後選代號會自動填入價格；右上角「更新報價」會一次更新全部持股；距離上次更新超過 15 分鐘，打開網頁時會自動更新。

隱私說明：金鑰只存在你的瀏覽器，不會出現在備份檔。查報價時只會把**股票代號**送給 Finnhub，股數與金額不會離開你的裝置。不設定金鑰也可以用，價格自己手動填即可。

## 備份（很重要）

資料存在瀏覽器裡，清除瀏覽器資料、換手機或換瀏覽器都會不見。

- 「⋯ → 匯出備份」會下載 `rebalance-backup-日期.json`，請存到雲端硬碟等安全的地方。
- 換裝置時用「⋯ → 從備份匯入」還原。
- 超過 30 天沒備份（或開始使用 3 天後還沒備份過），頁面上方會出現黃色提醒。
- iPhone 的 Safari 太久沒開啟網站可能會清掉網站資料，建議用「分享 → 加入主畫面」，並定期匯出。

## 在自己電腦上開啟

直接用瀏覽器打開 `site/index.html` 就能使用，不需要安裝任何東西。用本機檔案開啟時，資料和 GitHub Pages 網址上的資料是分開的，需要用匯出 / 匯入搬移。

## 開發

```
site/                網站本體（GitHub Pages 只發布這個資料夾）
  index.html
  styles.css
  data/symbols.js    美股代號清單（自動產生）
  js/calc.js         權重、區間狀態、調整金額
  js/editing.js      拖曳規則、合計補正、快速套用、新增 / 刪除板塊
  js/search.js       代號模糊搜尋
  js/quotes.js       Finnhub 報價查詢
  js/store.js        資料格式、瀏覽器儲存、匯出入
  js/app.js          畫面與互動
scripts/build-symbols.js   重新產生代號清單
tests/               單元測試
design/              設計稿（不會發布）
openspec/            規格與規劃文件（不會發布）
```

執行測試（需要 Node.js 18 以上，不需要安裝套件）：

```bash
npm test
```

重新產生美股代號清單（從 Nasdaq Trader 公開代號目錄下載）：

```bash
node scripts/build-symbols.js
```

本機預覽：

```bash
python -m http.server 8765 --directory site
```

## 部署

`.github/workflows/deploy.yml` 會在推送到 `main` 時先執行測試，通過後只把 `site/` 部署到 GitHub Pages。

第一次設定：

1. 在 GitHub 建立 repo（免費帳號的 Pages 需要公開 repo；repo 裡只有程式碼與範例資料，沒有你的持股）。
2. 推送 `main` 分支。
3. 到 repo 的 **Settings → Pages**，把 **Source** 設為 **GitHub Actions**。
4. 到 **Actions** 分頁確認「部署到 GitHub Pages」執行成功，網址會顯示在執行結果裡。
